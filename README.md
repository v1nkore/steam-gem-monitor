# Steam Dota 2 Unusual Gem Monitor

Инструмент для **арбитража Frostbloom** в Dota 2. Мониторит торговую площадку Steam и
присылает в **Telegram** уведомление, когда появляется **новый лот с заявленным гемом
Frostbloom**, с ценой этого лота, ценой самого дешёвого лота предмета («пол») и разницей
между ними. Идея: поймать Frostbloom, выставленный у пола (по дефолтной цене), купить и
перепродать с премией за Frostbloom.

Работает 24/7 **бесплатно** на GitHub Actions (cron каждые ~10 минут). Свой компьютер
держать включённым не нужно.

---

## Важно: про самоцветы и «не подтверждено»

Steam **не отдаёт настоящий сокетнутый гем** в данных торговой площадки. Единственное
место, где вообще встречается название гема, — это **описание лота, которое пишет сам
продавец** (и которое легко подделать). У «чистого» лота без правки описания информации
о геме нет вообще.

Поэтому проверить *реальный* гем можно только **инспектом предмета в самой игре**. Скрипт
показывает гем ровно так, как его заявил продавец, с честной пометкой **⚠️ «не
подтверждено»**. Дальше решаешь ты.

## Как это работает (коротко)

Для каждого предмета из `config.json` скрипт постранично читает все лоты (обычным
HTTP-запросом, без логина и браузера), считает **пол** (самый дешёвый лот), находит лоты,
у которых в описании заявлен **Frostbloom**, и по **новым** Frostbloom-лотам шлёт в Telegram
их цену и разницу с полом. При **первом** запуске молча запоминает уже висящие Frostbloom-лоты.

Пример сообщения:

```
💎 Unusual Northern Blight Style
Новых Frostbloom-лотов: 1
Самый дешёвый лот предмета (пол): $43.67

• Frostbloom $47.09 — дороже пола на $3.42 (+8%)

⚠️ гем заявлен продавцом, не подтверждён — проверь инспектом в игре
```

Если Frostbloom-лот **≤ пола** — в строке появится **🔥 «возможный флип»**.

Раз в час (`DIGEST_HOURS`) дополнительно приходит **таблица «текущая ситуация»** по всем
предметам: герой, шмотка, цена самого дешёвого Frostbloom-лота, пол и разница (строки у
пола помечены `*`), плюс **кликабельные ссылки на каждую шмотку**. Мгновенные пинги о новых
лотах приходят независимо от дайджеста.

Гем определяется строго по **гем-атрибуту** в описании лота (`''…Frostbloom…''`) — слово
`frostbloom` в данных лота встречается только там, не в названии/сете/ссылках. Ловятся все
формы записи продавца: `''Frostbloom''`, `''Frostbloom Unusual Effect Gem''`,
`''Unusual Effect Gem Frostbloom''`. Но это всё равно текст продавца — Steam настоящий гем
не отдаёт, поэтому пометка «проверь инспектом» остаётся.

- `monitor.py` — весь скрипт (только стандартная библиотека Python, зависимостей нет).
- `config.json` — список отслеживаемых предметов.
- `state.json` — какие Frostbloom-лоты уже видели (создаётся автоматически).
- `.github/workflows/monitor.yml` — запуск по расписанию на GitHub Actions.

## Что отслеживается сейчас

10 предметов: Northern Blight Style (Invoker), Light of the Forgotten Renegade, Claws of
the Grey Ghost (Lycan), Claws of the Crystal Drift (Ursa), Frostreach Brigands Axes
(Alchemist), Powdersled Rookery Cannon (Techies), Crown of Curious Coldspell (Puck), Lumpo

Сменить отслеживаемый гем можно переменной `TRACK_GEM` (по умолчанию `frostbloom`).

## Добавить предмет под отслеживание

1. Открой нужный Unusual-предмет на площадке Steam.
2. Скопируй URL страницы предмета (фильтр по гему не нужен — отслеживаются все лоты).
3. Вставь строкой в `targets` в `config.json`:

```json
{
  "targets": [
    "https://steamcommunity.com/market/listings/570/Unusual%20Northern%20Blight%20Style",
    "https://steamcommunity.com/market/listings/570/<Другой%20предмет>"
  ]
}
```

Можно и с человекочитаемым названием: `{ "url": "...", "label": "Моё название" }`.
Хвост `?filter=...` в ссылке не мешает — он просто игнорируется.

## Уведомления об ошибках

Чтобы «тишина» однозначно значила «всё работает, просто нет новых лотов», скрипт
сам сообщает, когда что-то ломается:

- **⚠️ Проблема в мониторинге** — если предмет не удалось просканировать (сеть,
  или Steam вернул нечитаемый ответ — признак блокировки IP / смены формата).
  Алерт приходит только после **3 неудач подряд** (разовые сетевые блипы и краткий
  троттлинг Steam игнорируются), дальше — напоминание не чаще раза в 12 ч, пока не
  починишь. В сообщении есть ссылка на логи запуска GitHub Actions.
- **✅ Мониторинг восстановился** — когда предмет снова читается нормально.
- **🛑 Фатальная ошибка** — если скрипт упал целиком (например, битый `config.json`);
  заодно падает и сам workflow (видно красным в Actions).

Опционально можно включить **heartbeat** — раз в сутки сообщение «жив, ошибок нет».
Это ловит даже случай «cron вообще перестал запускаться». Чтобы включить, добавь в
`.github/workflows/monitor.yml` в блок `env:` шага *Run monitor* строку:

```yaml
          HEARTBEAT_HOURS: "24"
```

## Настройка Telegram

1. В Telegram напиши **@BotFather** → `/newbot` → задай имя → получишь **токен бота**
   вида `123456789:AA...`.
2. Напиши своему новому боту любое сообщение (например `/start`) — иначе он не сможет
   тебе писать.
3. Узнай свой **chat_id**: напиши боту **@userinfobot** (пришлёт твой numeric id),
   либо открой `https://api.telegram.org/bot<ТОКЕН>/getUpdates` и найди `"chat":{"id":...}`.

Проверить локально (без реальной отправки) можно так:

```bash
DRY_RUN=1 python3 monitor.py
```

Реальная отправка локально:

```bash
TELEGRAM_BOT_TOKEN=xxxx TELEGRAM_CHAT_ID=yyyy python3 monitor.py
```

## Хостинг: GitHub Actions (бесплатно, 24/7)

1. Создай **публичный** репозиторий на GitHub и залей туда эти файлы
   (у публичных репозиториев минуты Actions не ограничены; токен всё равно хранится
   в секретах, не в коде).
2. `Settings → Secrets and variables → Actions → New repository secret`, добавь два:
   - `TELEGRAM_BOT_TOKEN`
   - `TELEGRAM_CHAT_ID`
3. Во вкладке **Actions** включи workflow (кнопка «I understand… enable»).
4. Готово. Скрипт будет запускаться каждые ~10 минут, сам коммитить `state.json`
   и слать уведомления о новых frostbloom-лотах.

Первый запуск можно сделать вручную: **Actions → steam-gem-monitor → Run workflow**.

Нюансы GitHub cron:
- Минимальный интервал — 5 минут, при высокой нагрузке бывают задержки в
  несколько минут. Для «поймать редкий лот» это обычно ок, но не мгновенно.
- Если в репозитории 60 дней нет активности, GitHub отключает расписание —
  просто зайди и включи снова (или сделай любой коммит).

### Альтернатива для более точного тайминга

Если нужен запуск чаще/стабильнее (до 1 минуты) — можно перенести логику на
**Cloudflare Workers + Cron Triggers + KV** (тоже бесплатный тариф; состояние
хранится в KV вместо `state.json`). Это отдельный порт на JS; текущий Python-скрипт
самодостаточен и рекомендуется как стартовый вариант.

## Локальный запуск / переменные

| Переменная            | По умолчанию | Назначение                                            |
|-----------------------|--------------|-------------------------------------------------------|
| `TELEGRAM_BOT_TOKEN`  | —            | Токен бота                                             |
| `TELEGRAM_CHAT_ID`    | —            | Куда слать                                             |
| `DRY_RUN`             | `0`          | `1` — ничего не слать, только печатать                 |
| `NOTIFY_ON_FIRST`     | `0`          | `1` — уведомлять и о том, что уже висит при 1-м запуске|
| `MAX_PAGES`           | `3`          | Сколько страниц (дешёвых лотов) сканировать на предмет  |
| `REQUEST_DELAY`       | `5`          | Пауза (сек) между запросами к Steam                    |
| `TRACK_GEM`           | `frostbloom` | Какой гем отслеживать (по заявке в описании)            |
| `ERROR_THRESHOLD`     | `3`          | Сколько неудач подряд до алерта в TG (гасит блипы)     |
| `DIGEST_HOURS`        | `1`          | Как часто слать таблицу «текущая ситуация» (0 = выкл)   |
| `ERROR_REMINDER_HOURS`| `12`         | Как часто напоминать, пока ошибка не устранена          |
| `HEARTBEAT_HOURS`     | `0`          | `24` — раз в сутки слать «жив, ошибок нет» (0 = выкл)   |

Никаких `pip install` не требуется — только Python 3.

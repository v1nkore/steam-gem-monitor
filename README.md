# Steam Dota 2 Unusual Gem Monitor

Мониторит торговую площадку Steam (Dota 2) на появление **Unusual-предметов с
конкретным эффект-самоцветом** (Ethereal Gem) и присылает уведомление в **Telegram**
со ссылкой на предмет. Цена не важна — важен сам факт появления листинга.

Работает 24/7 **бесплатно** на GitHub Actions (по расписанию, cron каждые ~5 минут).
Свой компьютер держать включённым не нужно.

---

## Как это работает (коротко)

Новый интерфейс площадки Steam применяет фильтр по самоцвету (`?filter=frostbloom`)
на стороне браузера, поэтому скрипт делает надёжнее: он **сам читает самоцвет из
описания каждого листинга** и сравнивает с нужным. Всё это — обычным HTTP-запросом,
без логина и без браузера, поэтому легко хостится на бесплатном cron.

- `monitor.py` — весь скрипт (только стандартная библиотека Python, зависимостей нет).
- `config.json` — список отслеживаемых предметов (см. ниже).
- `state.json` — служебный файл: какие листинги уже видели (создаётся автоматически).
- `.github/workflows/monitor.yml` — запуск по расписанию на GitHub Actions.

При **первом** запуске по каждому предмету скрипт молча запоминает то, что уже висит
на площадке (чтобы не спамить существующими лотами), и присылает уведомления только
о **новых** появлениях.

`config.json` сейчас содержит **9 проверенных связок** (по каждой подтверждено, что

  Powdersled Rookery Cannon, Crown of Curious Coldspell, Lumpo and Rupertus.

Добавить/убрать предметы — 10 секунд (см. ниже).

### Про ценные самоцветы (ресёрч)

Самые дорогие Unusual-предметы Dota 2 держатся на редких **Ethereal Gems** (эффект)
в связке с **Prismatic Gems** (цвет). Наиболее ценные/желанные эффекты:

- **Ethereal Flame** — самый дорогой, особенно «legacy» экземпляры (рекордные куриеры
  уходили за десятки тысяч $).
- **Frostbloom** — из примера задачи.
- **Trail of the Burning Doom / Burning Doom** — редкий огненный след.
- **Pipe Bomb** и другие эффекты из старых сокровищ.

Ценность растёт, потому что носители (куриеры/иммортали) падают с шансом ~1–2% из
конкретных сокровищ, а нужный эффект — ещё реже. Точный редкий эффект у конкретного
предмета проще всего задать, **скопировав ссылку с уже выбранным фильтром** (ниже).

## Добавить предмет под отслеживание

1. Открой любой Unusual-предмет на площадке Steam.
2. В фильтре **«Самоцвет/эффект»** выбери нужный эффект.
3. Скопируй URL из адресной строки — там появится `?filter=<эффект>`.
4. Вставь его строкой в `targets` в `config.json`:

```json
{
  "targets": [
    "https://steamcommunity.com/market/listings/570/Unusual%20Northern%20Blight%20Style?filter=frostbloom",
    "https://steamcommunity.com/market/listings/570/<Другой%20предмет>?filter=ethereal_flame"
  ]
}
```

Если название фильтра в URL отличается от того, что написано в описании листинга,
используй расширенную форму с точным текстом для сравнения:

```json
{ "url": "https://steamcommunity.com/market/listings/570/<Предмет>?filter=<токен>",
  "match": "ethereal flame",
  "label": "Моё красивое название" }
```

`match` — слова, которые реально встречаются в описании самоцвета у листинга
(регистр не важен). Для большинства эффектов достаточно просто ссылки.

## Уведомления об ошибках

Чтобы «тишина» однозначно значила «всё работает, просто нет новых лотов», скрипт
сам сообщает, когда что-то ломается:

- **⚠️ Проблема в мониторинге** — если предмет не удалось просканировать (сеть,
  или Steam вернул нечитаемый ответ — признак блокировки IP / смены формата).
  Алерт приходит только после **2 неудач подряд** (разовые сетевые блипы игнорируются),
  дальше — напоминание не чаще раза в 12 ч, пока не починишь. В сообщении есть ссылка
  на логи запуска GitHub Actions.
- **✅ Мониторинг восстановился** — когда предмет снова читается нормально.
- **🛑 Фатальная ошибка** — если скрипт упал целиком (например, битый `config.json`);
  заодно падает и сам workflow (видно красным в Actions).

Опционально можно включить **heartbeat** — раз в сутки сообщение «жив, ошибок нет».
Это ловит даже случай «cron вообще перестал запускаться». Чтобы включить, добавь в
`.github/workflows/monitor.yml` в блок `env:` шага *Run monitor* строку:

```yaml
          HEARTBEAT_HOURS: "24"
```

## Настройка Telegram

1. В Telegram напиши **@BotFather** → `/newbot` → задай имя → получишь **токен бота**
   вида `123456789:AA...`.
2. Напиши своему новому боту любое сообщение (например `/start`) — иначе он не сможет
   тебе писать.
3. Узнай свой **chat_id**: напиши боту **@userinfobot** (пришлёт твой numeric id),
   либо открой `https://api.telegram.org/bot<ТОКЕН>/getUpdates` и найди `"chat":{"id":...}`.

Проверить локально (без реальной отправки) можно так:

```bash
DRY_RUN=1 python3 monitor.py
```

Реальная отправка локально:

```bash
TELEGRAM_BOT_TOKEN=xxxx TELEGRAM_CHAT_ID=yyyy python3 monitor.py
```

## Хостинг: GitHub Actions (бесплатно, 24/7)

1. Создай **публичный** репозиторий на GitHub и залей туда эти файлы
   (у публичных репозиториев минуты Actions не ограничены; токен всё равно хранится
   в секретах, не в коде).
2. `Settings → Secrets and variables → Actions → New repository secret`, добавь два:
   - `TELEGRAM_BOT_TOKEN`
   - `TELEGRAM_CHAT_ID`
3. Во вкладке **Actions** включи workflow (кнопка «I understand… enable»).
4. Готово. Скрипт будет запускаться каждые ~5 минут, сам коммитить `state.json`
   и слать уведомления о новых лотах.

Первый запуск можно сделать вручную: **Actions → steam-gem-monitor → Run workflow**.

Нюансы GitHub cron:
- Минимальный интервал — 5 минут, при высокой нагрузке бывают задержки в
  несколько минут. Для «поймать редкий лот» это обычно ок, но не мгновенно.
- Если в репозитории 60 дней нет активности, GitHub отключает расписание —
  просто зайди и включи снова (или сделай любой коммит).

### Альтернатива для более точного тайминга

Если нужен запуск чаще/стабильнее (до 1 минуты) — можно перенести логику на
**Cloudflare Workers + Cron Triggers + KV** (тоже бесплатный тариф; состояние
хранится в KV вместо `state.json`). Это отдельный порт на JS; текущий Python-скрипт
самодостаточен и рекомендуется как стартовый вариант.

## Локальный запуск / переменные

| Переменная            | По умолчанию | Назначение                                            |
|-----------------------|--------------|-------------------------------------------------------|
| `TELEGRAM_BOT_TOKEN`  | —            | Токен бота                                             |
| `TELEGRAM_CHAT_ID`    | —            | Куда слать                                             |
| `DRY_RUN`             | `0`          | `1` — ничего не слать, только печатать                 |
| `NOTIFY_ON_FIRST`     | `0`          | `1` — уведомлять и о том, что уже висит при 1-м запуске|
| `MAX_PAGES`           | `8`          | Сколько страниц листингов сканировать на предмет       |
| `REQUEST_DELAY`       | `3`          | Пауза (сек) между запросами к Steam                    |
| `ERROR_THRESHOLD`     | `2`          | Сколько неудач подряд до алерта в TG (гасит блипы)     |
| `ERROR_REMINDER_HOURS`| `12`         | Как часто напоминать, пока ошибка не устранена          |
| `HEARTBEAT_HOURS`     | `0`          | `24` — раз в сутки слать «жив, ошибок нет» (0 = выкл)   |

Никаких `pip install` не требуется — только Python 3.
